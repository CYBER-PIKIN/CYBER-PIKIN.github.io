Web Application Security Labs

Practicing structured testing of common web application weaknesses in intentionally vulnerable, authorized lab environments.

Objective

Build a repeatable workflow for identifying common application security issues, understanding their impact, and documenting practical remediation guidance.

Areas explored

  • Cross-Site Scripting (XSS)
  • Cross-Site Request Forgery (CSRF)
  • SQL injection
  • Broken access control
  • JSON Web Token (JWT) security concepts

Tools & environment

Burp SuiteOWASP ZAPDVWAOWASP Juice ShopKali Linux

Testing is performed only against intentionally vulnerable labs or systems where permission has been granted.

Methodology

  1. Understand the target application and define scope.
  2. Map inputs, routes, and authentication or authorization boundaries.
  3. Test one weakness at a time and record reproducible observations.
  4. Assess likely impact without causing unnecessary damage.
  5. Recommend defensive fixes and retest where possible.

Learning outcomes

This work supports practical familiarity with web testing tools, vulnerability classes, evidence collection, and clear security reporting. Individual lab findings vary by exercise; this page does not claim a production penetration test.
